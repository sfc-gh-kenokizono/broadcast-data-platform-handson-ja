# 放送データ基盤ハンズオン

**5局の視聴記録を取り込み、整え、グラフとAIから使えるようにする教材です。**

受け取った記録を、そのままグラフにしてよいのでしょうか？
同じ「ニュース」でも ` news ` と `NEWS` が混ざっていたら、別のジャンルとして集計されてしまいます。
また、同じ端末が2つの局を見たとき、局別の端末数を足すと二重に数えてしまいます。

このハンズオンでは、こうした点を確認しながら、データの取込から分析までを順番に体験します。
操作はSnowflakeのブラウザー画面 **Snowsight** が中心です。コードとデータは用意してあります。

## 最初に開くファイル

👉 **[第1章 セットアップ](docs/01_setup.md)から始めてください。**

まだ教材のGit Workspaceがなくても大丈夫です。
最初のSQLは、GitHubで直接開けます。

**[sql/01_setup.sql を開く](https://github.com/sfc-gh-kenokizono/broadcast-data-platform-handson-ja/blob/main/sql/01_setup.sql)**

1. 第1章の[実行前の確認](docs/01_setup.md#実行前の確認)で、利用アカウントと管理者の案内を確認します。
2. 上のSQLをSnowsightへ貼り付け、第1〜5節を順に実行します。環境の準備、Git API統合、リポジトリ接続が含まれています。
3. 第1章の[Git Workspace作成手順](docs/01_setup.md#受講用git-workspaceを作る)に沿って、教材を自分の作業場所へ取り込みます。
4. 作成したWorkspaceで [sql/02_load_parquet.sql](sql/02_load_parquet.sql) を開き、データを読み込みます。

| 章 | 何をする？ | 終わるとどうなる？ |
|---|---|---|

### データはどこを通る？

```text
各局のファイル（Parquet / 内部ZSTD圧縮）
   ├─ NW01用WH → 整形 → テスト → NW01の集計表 → テスト
   ├─ NW02用WH → 整形 → テスト → NW02の集計表 → テスト
   ├─ NW03用WH → 整形 → テスト → NW03の集計表 → テスト
   ├─ NW04用WH → 整形 → テスト → NW04の集計表 → テスト
   └─ NW05用WH → 整形 → テスト → NW05の集計表 → テスト
                                ↓ 全局成功後
                    共通WHで5局の集計表を統合 → テスト
                                ↓
                       COMMON.VIEWING_DAILY
                         ├─ 学習・登録・予測 → ML.PREDICTIONS
                         ├─ Streamlitで実績と予測を見る
                         └─ 指標の定義 → Agent → CoWorkで質問
```

**原本を先に全部まとめるのではなく、各局で整えてからまとめます。**
ウェアハウス（WH）はSQLの計算担当です。保存先のDB・テーブルとは別です。
局ごとの計算を分けることで、どの局の処理に計算資源を使ったかを確認しやすくします。

## 始める前に

- 講師が案内する演習用Snowflakeアカウントを使います。
- 管理者による初期準備と、利用ロールの付与が必要です。
- NotebookのPython実行環境は、講師が案内するものを使います。
- ローカルPCへのPython・dbt・Cortex Code Desktopのインストールは不要です。
- この固定名の教材環境は、1アカウントに1組を想定しています。

教材DBは `BCAST_PLATFORM_HANDSON` です。
同じアカウントに参加者別の独立環境を作る場合は、教材全体の名前を調整する必要があるため講師へ確認してください。
旧教材の `BCAST_VIEWING_HANDSON` は変更しません。

**本編は3時間の枠を目標としていますが、実測の所要時間は未確認です。**
画面が手順と違う、必要な項目が選べない、エラーが出る場合は、その場で講師へ確認します。

## 使うデータ

架空の200端末による、2026年7月1日〜30日の視聴記録です。
全体で18,000行、各局3,600行あります。

1行は「いつから、いつまで、どのジャンルを見たか」という1回の記録です。
同じ端末IDは、局をまたいでも同じ端末を表します。端末を照合する作業は済んでいる想定です。

第3章では、スポーツへの関心を模した架空の正解ラベルを使います。
**実在する人の関心・年齢・性別を特定する教材ではありません。**
各局のリーチが同じになる等の人工的な設定もあり、市場規模や本番の予測精度の根拠には使えません。

## 必須と補足の区別

- **本編**：第1〜5章。StreamlitはWHで動かす推奨手順を使います。
- **任意の補足**：[基本SQL・Cortex Search・定期実行の考え方](supplemental/README.md)。省略しても本編を完了できます。
- **講師デモのみ**：App Runtime。受講者は作成しません。現在は準備中で、配布資材には含めていません。
- **対象外**：DCR、外部モデルファイルの持ち込み、高度な自動再学習。
