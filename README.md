# 放送データ基盤ハンズオン

**5局の視聴記録を取り込み、整え、グラフとAIから使えるようにする教材です。**

操作はSnowflakeのブラウザー画面 **Snowsight** が中心です。コードと合成データは用意済みで、自分でGitHubリポジトリを作る必要はありません。

## 最初にすること

**[第1章 セットアップ](docs/01_setup.md)から始めてください。**

| どこで開く？ | 何をする？ | 成功の目印 |
|---|---|---|
| [第1章の実行前確認](docs/01_setup.md#実行前の確認) | 演習用アカウント、権限、既存環境を確認 | この固定名の教材環境を使ってよいと講師から案内される |
| GitHubの [sql/01_01_setup.sql](https://github.com/sfc-gh-kenokizono/broadcast-data-platform-handson-ja/blob/main/sql/01_01_setup.sql) → Snowsight | SQLを貼り付け、第1〜5節を順に実行 | 第5節の `LIST` で8個のParquetが見える |
| Snowsightの [Git Workspace作成](docs/01_setup.md#受講用git-workspaceを作る) | `main` から自分用Workspaceを作る | 教材ファイルが開ける |
| Workspaceの [sql/01_02_load_parquet.sql](sql/01_02_load_parquet.sql) | `COPY FILES`、8本の `COPY INTO`、件数確認を順に実行 | 8本が成功し、8表の件数が期待値と一致 |

取込元は `main` の `/branches/main/data/`、データ版は `F1_SIGNAL_V2` です。演習中は配布元・ステージのファイルを変更しません。取得できない場合や既存環境がある場合は、削除や初期化をせず講師へ確認します。再実行では `COPY FILES` を繰り返さず、[第1章の再実行手順](docs/01_setup.md#もう一度実行するとき)に従います。

## 教材の流れ

| 章 | 何をする？ | 完了すると |
|---|---|---|
| [1. セットアップ](docs/01_setup.md) | 準備済みの8ファイルを取り込む | 5局の原本を別々の表で読める |
| [2. dbt](docs/02_dbt.md) | 重複・不正区間・表記を整え、日次と分単位で集計 | 共通の日次実績表と分内視聴端末数表ができる |
| [3. MLOps](docs/03_mlops.md) | 合成世帯のF1在籍を推定する分類モデルを評価・登録 | 在籍確率とモデル版を結果に残せる |
| [4. Streamlit](docs/04_streamlit.md) | 5局横断の実績と予測を分析画面に表示 | KPI、局・ジャンル構成、毎分パルス、モデル予測を切り替えて見られる |
| [5. Agent・CoWork](docs/05_agent.md) | 指標を定義し、質問用Agentを作る | 日本語で視聴実績を質問できる |

データは、各局のRAWを局別WHで整形・テストしてから、共通WHで統合します。WHはSQLの計算を担当する場所で、保存先ではありません。5本の局別処理は各4モデル・15テスト、共通処理は2モデル・6テストです。合計22モデル・81テストは、計6回の `build` の中で自動実行されます。

```text
8個のParquet → 5局のRAW → 局別の整形・集計 → 共通の日次・分単位マート
                                                   ├─ MLOps
                                                   ├─ Streamlit
                                                   └─ Agent・CoWork
```

## 始める前に

- 講師が案内する演習用Snowflakeアカウントを使います。業務用アカウントでは実行しません。
- 管理者による初期準備、利用ロールの付与、NotebookのPython実行環境が必要です。
- ローカルPCへのPython・dbt・Cortex Code Desktopのインストールは不要です。
- 教材DBは `BCAST_PLATFORM_HANDSON` です。固定名の環境は1アカウントに1組を想定しています。
- 参加者別に独立環境を作る場合は、教材全体の名前調整が必要なため講師へ確認します。
- 既存の別教材や業務用環境は変更しません。

**本編は3時間の枠を目標としていますが、実測の所要時間は未確認です。** 画面や結果が手順と違う場合は、設定を推測して変更せず講師へ確認してください。

## 使うデータ

**すべて教材用の合成データで、実際の視聴ログではありません。** 期間は2026年5月1日〜7月31日の92日間、対象は5局・テレビ20,000台です。Parquetは局別ログ5個、番組マスタ、放送予定、ラベルの計8個です。

| 段階・指標 | V2配布データの期待値 |
|---|---:|
| 入力（5局のRAW合計） | 1,050,648行 |
| 重複・不正区間を除いた視聴記録 | 1,050,000件 |
| 日次集計 | 1,045,120行 |
| 視聴区間を分単位に展開 | 13,532,927行 |
| 局・分ごとの集計 | 548,535行 |
| 総視聴時間 | 約12,511,642.266667分 |

番組マスタ60行は、5局それぞれに12種類、合計60種類の番組タイプを定義したものです。放送予定8,747行は、その番組タイプを3か月の各放送枠へ繰り返し割り当てたものです。

分内視聴端末数は「その1分のどこかで視聴していたテレビの台数」です。ある瞬間の同時視聴台数や視聴者数ではなく、局別の値を足して全局リーチにはできません。総視聴時間と分単位へ展開した行数も別の値です。詳細は[第2章](docs/02_dbt.md)で扱います。

第3章では、合成世帯にF1（20〜34歳の女性）が在籍するかを推定します。正解ありは2,000台（在籍あり344台、在籍なし1,656台）、正解不明は18,000台です。不明は `NULL` のまま扱い、0にしません。学習1,200台・調整用400台・最終評価400台を使い、XGBoost分類モデル `TV_F1_PRESENCE_MODEL` の `V1` を登録します。特徴量重要度と、Model Registryの `explain` が返すSHAP値で判断理由を確認し、同じ登録モデルで予測します。再実行時は既存の `V1` を削除して同じ `V1` を登録します。判定境界は0.50です。評価値はNotebookを実行して確認します。

## 用語と範囲

| 用語 | この教材での意味 |
|---|---|
| dbt | SQLの加工処理と結果のテストをまとめて動かす道具 |
| マート | 分析しやすい単位にまとめた表 |
| Notebook | 説明・Pythonコード・結果を順番に実行するファイル |
| Streamlit | Pythonでグラフや操作画面を作る仕組み |
| Semantic View | 指標と分析の切り口を定義するもの |
| Agent / CoWork | 分析ツールを使う質問役 / Agentへ日本語で質問する画面 |

本編は第1〜5章です。StreamlitはWHで動かす推奨手順を使います。[基本SQL・Cortex Search・定期実行の考え方](supplemental/README.md)は任意です。App Runtimeは講師デモのみで、現在の配布資材には含みません。DCR、外部モデルファイルの持ち込み、高度な自動再学習は対象外です。

## 終了するとき

まず[Notebookサービスを停止](docs/03_mlops.md#7-notebookサービスを停止する)します。ブラウザーを閉じるだけでは停止しません。

教材環境を削除する場合は[第1章の後片付け](docs/01_setup.md#後片付け)を読みます。[cleanup.sql](sql/cleanup.sql)は成果物ごと削除するため、通常の演習中には実行しないでください。
