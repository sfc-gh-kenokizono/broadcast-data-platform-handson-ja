# 第3章 MLOps体験

合成の視聴履歴から「スポーツへの関心」を予測するモデルを作ります。学習するだけで終わらず、モデルに名前と版を付けて登録し、その登録版から予測して結果を保存します。

> ラベルは教材用の架空の正解です。実在する人の関心・年齢・性別や、誰が視聴していたかを特定するものではありません。

## 1. Notebookを開く

1. 第2章で5局と共通マートのbuild・テストがすべて成功したことを確認します。
2. SnowsightのGit Workspaceで `notebooks/03_mlops.ipynb` を開きます。
3. 講師が案内するPython実行環境に接続します。ローカルPCにPythonを入れる必要はありません。
4. 実行ロールを `BCAST_PLATFORM_ENGINEER_ROLE` にします。Notebookは共通WH、`BCAST_PLATFORM_HANDSON`、`ML`スキーマを選択します。
5. `numpy`、`pandas`、`scikit-learn`、`snowflake-snowpark-python`、`snowflake-ml-python` が利用できることを確認します。

WorkspaceのPython実行には利用可能なcompute poolと権限が必要です。第1章のSQLはcompute poolを準備しません。接続できない場合は講師に確認し、管理者ロールへ切り替えて進めないでください。

## 2. 上から順に実行する

Notebookの説明を読み、コードセルを1つずつ実行します。途中でエラーが出たら、その原因を確認してから進みます。

| 段階 | 行うこと | 確認すること |
|---|---|---|
| 準備 | セッション・実行場所・モデル名と版を設定 | 指定ロール、共通WH、初期版V1 |
| 特徴量 | 端末ごとに視聴履歴を集計 | 200台、欠損・重複なし |
| 学習・評価 | 学習用80台と評価用20台に分割 | 同じ端末が両方に入っていない |
| 登録 | 評価したモデルをRegistryへ登録 | モデル名・版・評価値 |
| 推論 | 登録した版で200台を予測 | 端末と予測の対応、予測は0か1 |
| 保存 | 予測結果と使用した版を保存 | 200行を読み戻して照合 |

学習はNotebookのPython環境、端末集計と登録モデルの推論は共通WHで行います。Python実行基盤とWHの消費は別です。

## 3. モデルの入力を理解する

入力は `COMMON.VIEWING_DAILY` と `RAW.DEVICE_LABELS` です。視聴履歴を端末ごとに集計し、次の7項目をモデルに渡します。

- ニュース・ドラマ・バラエティ・アニメ・スポーツの視聴時間の割合：5項目。
- 総視聴時間と総視聴回数：2項目。

端末IDは結果を対応付けるためのキーです。端末IDや正解ラベルそのものはモデルの入力にしません。

200台のうち正解があるのは100台で、0と1が各50台です。残り100台の正解はNULLのまま使います。不明を0に置き換えません。正解のある100台を、学習80台・評価20台に分けます。

## 4. 評価結果を読む

決定木モデルと、「常に多数派のクラスを答える」比較用モデルを同じ20台で評価します。accuracyは正解した割合、balanced accuracyはクラスごとの正解率を平均した指標です。

大切なのは学習に使っていない端末で採点することです。全200台への予測には学習済み端末も含まれるため、その全件を使って精度を評価しません。この教材の結果を実際の視聴者への予測精度として扱わないでください。

## 5. モデルを登録する

登録先は `BCAST_PLATFORM_HANDSON.ML.SPORTS_INTEREST_MODEL`、初期版は `V1` です。学習・評価したモデルそのものを登録し、評価値も記録します。

同名・同版があると停止します。再実行する場合は、初期設定セルの `MODEL_VERSION` を `V2` など未使用の版へ変えて、上から実行します。以前のモデルを削除して通す手順ではありません。

学習に使ったscikit-learnの版を指定し、WAREHOUSEでの推論用に登録します。依存パッケージを解決できなければ停止するので、講師に確認してください。

## 6. 登録したモデルで予測する

登録セルが返したモデル版の `predict` を使って予測します。学習時のローカルモデルで予測した値を、そのまま保存する処理ではありません。

入力の特徴量と予測を対応付けて、200台の結果へ戻します。戻り行の順番だけで端末を割り当てません。予測が欠けている場合や0・1以外の場合は停止します。

## 7. 保存を許可する

保存セルの初期値は次のとおりです。

```python
SAVE_RESULTS = False
```

このままでは確認メッセージとともに停止し、結果テーブルを書き換えません。推論まで成功し、既存の予測結果を置き換えてよいと確認した場合だけ `True` に変更して保存セルを実行します。モデル登録は保存確認より前に行われます。

保存先は `BCAST_PLATFORM_HANDSON.ML.PREDICTIONS` です。履歴の追加ではなく、テーブル内容を置き換えます。

| 列 | 内容 |
|---|---|
| DEVICE_ID | 端末ID |
| PREDICTED_SPORTS_FAN | 予測クラス0または1 |
| MODEL_NAME | 使用したモデル名 |
| MODEL_VERSION | 使用した版 |
| PREDICTED_AT | UTCでの保存時刻 |

保存後に200行を読み戻し、端末と予測値・モデル名・版を照合します。「200台の結果を保存・照合しました」と表示されれば完了です。照合が失敗しても保存は自動的に取り消されないので、後続へ進まず講師へ報告してください。
