# 第3章 MLOps体験: データを見て、モデルを作り、Snowflakeで使う

第2章で作成した5局の視聴データを使い、テレビに対応する世帯にF1層（20〜34歳の女性）がいる確率を予測します。

すべて教材用の合成データです。実在する個人の属性や人数を示すものではありません。

## この章で行うこと

```text
5局の視聴データ
  ↓ テレビ1台につき1行へ集計
12項目の視聴傾向と正解ラベル
  ↓ データを表とグラフで観察（EDA）
XGBoostを学習・評価
  ↓ モデル全体の判断材料を確認
モデル、版、評価指標、説明機能をModel Registryへ登録
  ↓ 登録モデルのSHAP値で判断理由を確認
Snowflake上の登録モデル
  ↓
登録モデルで20,000台を予測
  ↓
予測結果をSnowflakeへ保存
```

機械学習では、人が「この条件ならF1層あり」というルールを直接書きません。正解が分かっている2,000台をモデルへ見せ、12項目の視聴傾向と正解の関係を学習させます。学習後は性能だけでなく、モデル全体が使った項目と1台ごとの判断理由も確認します。

Snowflakeでは、モデル本体だけでなく、版、評価指標、実行環境、予測関数、説明関数をModel Registryでまとめて管理できます。データやモデルを別システムへ移さず、登録した版をSnowflake上で説明と予測に使うところまでを体験します。

## 2. Notebookのセルを順番に実行する

各Markdown説明のすぐ下にあるコードセルを、上から1つずつ実行します。

### セル1: Notebookを準備する

**入力:** なし

**処理:**

- Snowflakeのセッションを取得
- ロール、ウェアハウス、データベースを設定
- pandas、scikit-learn、XGBoost、Snowpark、Snowflake MLを読み込み
- モデル名と版を設定

この章では **XGBoost** を使います。小さな決定木を組み合わせ、F1層がいる確率を0〜1で計算する分類モデルです。

**出力と成功の目印:**

```text
パッケージ: scikit-learn ... / XGBoost ...
準備完了: TV_F1_PRESENCE_MODEL V3
```

バージョン番号はRuntimeに含まれるものが表示されます。追加のパッケージインストールは行いません。

### セル2: 予測に使うデータを準備する

**入力:** `BCAST_PLATFORM_HANDSON.COMMON.VIEWING_DAILY`

**処理:** 5局の視聴データをテレビ1台につき1行へまとめ、次の12項目を作ります。

- 8ジャンルの視聴割合
- 総視聴時間
- 視聴回数
- 視聴した日数
- 1回あたりの平均視聴時間

20,000台のうち、正解ラベルがある2,000台を学習と評価に使います。

**出力と成功の目印:**

```text
データ準備完了: 全体 20000台 / 学習・評価対象 2000台
```

あわせて、テレビ1台につき1行になったデータの先頭5行が表示されます。

### セル3: 学習データを観察する（EDA）

EDAは、モデルを作る前にデータの中身や傾向を確認する作業です。

**入力:** 正解ラベルがある2,000台から分けた、学習用1,200台

**処理:**

- F1層なし・ありの台数を数える
- 主な視聴項目について、2グループの平均を比べる

**出力と成功の目印:**

- 学習用1,200台に含まれるF1層なし・ありの台数
- `DRAMA_SHARE`、`VARIETY_SHARE`、`ANIME_SHARE`、`TOTAL_MINUTES`、`ACTIVE_DAYS` のグループ別平均

ここでは、モデルが学べる視聴傾向の違いがあることを表で確認します。

### セル4: ジャンル別の視聴傾向をグラフで見る

**入力:** 学習用1,200台の8ジャンルの視聴割合

**処理:** F1層なし・ありのグループごとに平均し、横に並べた棒グラフを作ります。

**出力と成功の目印:** 「学習データのジャンル別平均視聴割合」という棒グラフが表示されます。

棒の高さに違いがあれば、その傾向をモデルが予測の手がかりとして使えます。ただし、モデルは1項目だけで判断せず、12項目を組み合わせます。

### セル5: XGBoostを学習・評価する

**入力:** 2,000台の12項目と正解ラベル

**処理:**

| 用途 | 台数 | 何に使うか |
|---|---:|---|
| 学習 | 1,200台 | 12項目と正解の関係をモデルに学ばせる |
| 調整 | 400台 | 学習後のモデルを確認する |
| 評価 | 400台 | 学習に使っていないデータで性能を確認する |

XGBoostは、小さな決定木を順番に作り、前の木が間違えた部分を次の木で補いながら分類します。12項目を組み合わせ、F1層がいる確率を計算します。

**出力と成功の目印:**

```text
学習データ: 1200台 / 調整データ: 400台 / 評価データ: 400台
モデル: XGBoost
評価完了
```

続けて、ROC AUC・適合率・再現率が表で表示されます。数値を暗記する必要はありません。学習に使っていないデータで評価できたことを確認します。

### セル6: モデル全体の判断材料を見る

**入力:** 調整用400台と学習済みモデル

**処理:** 12項目を1つずつ入れ替え、調整用データのROC AUCが平均でどれだけ変わるかを比べます。正の値が大きい項目ほど、入れ替えたときの性能低下が大きく、モデル全体が強く使っている判断材料です。

**出力と成功の目印:** 「モデル全体の特徴量重要度」という横棒グラフが表示されます。

この重要度は予測に使われた度合いであり、原因や因果関係を証明するものではありません。

### セル7: モデルをModel Registryへ登録する

**入力:** 学習・評価済みのXGBoostモデル

**処理:** モデルを `TV_F1_PRESENCE_MODEL` の初期版 `V3` としてModel Registryへ登録します。V3が既存の場合は、Notebook先頭の `MODEL_VERSION` で選んだ未使用版を使います。学習データの一部も、SHAP値を計算するときの比較基準として登録します。

Model Registryでは、モデル本体、版、評価指標、Pythonとライブラリの環境、予測関数、説明関数を同じSnowflakeオブジェクトとして管理します。ロールの権限で利用者を制御でき、登録した版を後続処理から同じ名前で呼び出せます。

**出力と成功の目印:**

```text
モデル登録完了: TV_F1_PRESENCE_MODEL （選択した未使用版）
```

続けて、予測に使う `predict_proba` と、判断理由を返す `explain` が表示されます。

### セル8: 登録モデルの判断理由をSnowflakeで説明する

**入力:** Model Registryの `TV_F1_PRESENCE_MODEL` で選択した版と調整用100台

**処理:** 登録モデルの `explain` をSnowflakeのウェアハウスで実行し、SHAP値を取得します。

- 全体表示: 100台について、各項目が予測を動かした大きさの平均
- 1台の表示: 各項目が「F1層あり」または「なし」のどちらへ働いたか

SHAP値はブラックボックスになりやすいモデルの判断を入力項目へ分けて示します。プラスは「F1層あり」の方向、マイナスは「なし」の方向です。値は確率の増減そのものではなく、XGBoost内部の生のモデルスコアへの寄与です。比較基準となるスコアに各項目のSHAP値を加え、最後に確率へ変換します。因果関係を示すものではありません。

**出力と成功の目印:** 「登録モデルのSHAP重要度」と「1台の予測を動かした項目」の2つのグラフ、および次のメッセージが表示されます。

```text
Snowflake上の登録モデルでSHAP説明完了: 100台
```

ここでは、手元の学習済みモデルを直接説明するのではなく、**Model Registryへ登録した版そのもの**を説明しています。説明と予測で同じ管理対象を使えることがSnowflake MLOpsのポイントです。

### セル9: 登録したモデルで20,000台を予測する

**入力:** 20,000台それぞれの12項目

**処理:** Model Registryへ登録したモデルの `predict_proba` を呼び出します。

**出力:**

- `PROB_F1`: F1層がいる確率（0〜1）
- `PREDICTED_HAS_F1`: 確率が0.50以上なら1、未満なら0

**成功の目印:**

```text
予測完了: 20000台
```

あわせて、`DEVICE_ID`・確率・判定の先頭5行が表示されます。

### セル10: 予測結果を保存する

**入力:** 20,000台の端末ID・確率・判定・モデル版

**処理:** `BCAST_PLATFORM_HANDSON.ML.PREDICTIONS` に保存します。

最初は `SAVE_RESULTS = False` のまま実行します。次のメッセージが表示されたら、保存確認ができています。

```text
保存する場合はSAVE_RESULTSをTrueに変更してください。
```

同じセルの先頭を次のように変更し、もう一度実行します。

```python
SAVE_RESULTS = True
```

**出力と成功の目印:**

```text
保存完了: BCAST_PLATFORM_HANDSON.ML.PREDICTIONS 20000行
```

## 3. Snowflake MLOpsで確認したこと

この章では、次のものをSnowflakeの中でつなげました。

| 管理対象 | この章で確認したこと |
|---|---|
| データ | Snowflake上の視聴マートから特徴量を作る |
| モデル | XGBoostを学習し、未使用データで評価する |
| 解釈 | 全体の特徴量重要度と、1台ごとのSHAP値を確認する |
| 版とメタデータ | モデル名、選択した版、評価指標、依存ライブラリをModel Registryで管理する |
| 利用 | 登録モデルの `explain` と `predict_proba` をSnowflake上で呼び出す |
| 成果物 | 20,000台の予測をモデル版と閾値付きでテーブルへ保存する |

これにより、学習用Notebookだけにモデルを閉じ込めず、同じ登録モデルを説明、予測、権限制御、後続アプリで再利用できます。

登録後に `predict_proba` または `explain` を確認できず停止した場合も、モデル版はすでに作成されています。既存版は削除せず、`MODEL_VERSION` を未使用版へ変更し、Notebookを先頭から実行します。
