# 補足教材（すべて任意）

3時間の本編に追加の必須作業はありません。このフォルダを丸ごと省略しても、本編の dbt・ML・Streamlit・Agent を進められます。対象は新教材 `BCAST_PLATFORM_HANDSON` のみです。旧教材や業務環境には接続しません。

## 基本 SQL

[01_basic.sql](01_basic.sql) は、エンジニアロールと共通WHを選択し、SELECT だけで学ぶ例です。データの作成・更新・削除や設定値の変更はしません。USE は現在のセッションの選択だけを変え、ユーザーの既定値は変えません。

- 冒頭の確認でアカウント・ロール・DB・WHが教材用であることを確認してから進みます。
- 共通マートの集計は、[第2章](../docs/02_dbt.md) の全5局と common の build・テスト合格後に実行します。マート行数はセッション数ではないため `SUM(SESSION_COUNT)` を使います。リーチは対象期間全体で端末IDを重複排除します。
- 最後の区間結合は `VALUES` 内だけで完結します。共通マート未作成でも、セットアップ後にこの文だけを選択実行できます。7行を3区間へまとめ、原本には書き戻しません。

### 結果キャッシュの見方

共通マートの SELECT を、文字列・ロール・設定・入力データを変えずに2回実行して比較します。永続化された結果が再利用される場合、再計算を省略できます。ただし、条件を満たしても再利用は保証されません。`USE_CACHED_RESULT` が無効な環境ではこの観察を省略し、本教材から設定を変更しません。

2回目が速いことだけでは証明になりません。Snowsight のクエリ履歴とプロファイルで、結果再利用の表示や実行内容を確認し、確認できなければ「未確認」と記録します。WH上のテーブルデータのキャッシュと結果キャッシュは別です。`RESULT_SCAN` は過去結果の再参照であり、同一SELECTが自動再利用された証明ではありません。この小規模教材で性能や削減率を評価しません。

### from-to を折り畳む

端末・局・ジャンルが同じで、重なる区間または終了と開始が一致する区間を結合します。半開区間 `[VIEW_FROM, VIEW_TO)` として扱い、空白時間は埋めません。直前1行の終了だけでなく、先行行すべての最大終了を使うことで、包含区間があっても誤って分割しません。

期待結果は同日の `08:00–08:50`（4行）、`09:00–09:20`（2行）、`10:00–10:05`（1行）の3行です。各行の `INPUT_ROWS = 7`、`FOLDED_ROWS = 3` も確認します。これは区間結合の専用フィクスチャで、本編データに重複があるという意味ではありません。本編のイベント件数・視聴分数の定義は変更しません。不正時刻、NULL、局をまたぐ競合の解決や日付境界での分割は対象外です。

## 定期実行を考える場合

ここではスケジュールを作成・有効化しません。将来の設計だけを整理します。

1. ロードの成功と対象期間・入力版を確定し、コード版も固定します。同じ実行単位の処理中は入力を更新しません。
2. `nw01` から `nw05` の build を、それぞれ同名 target と selector、対応する局別WHで実行します。各局のモデルとテストの成功、skip/errorなし、子SQLのWHを記録します。
3. 同じ実行単位の5局すべてが合格した場合だけ、`common` target / selector と共通WHで build します。上流を選ぶ `+` や無指定の全体 build は使いません。
4. common のモデルとテストが合格した場合だけ、下流で新しい実績を採用します。テーブルの存在、古い成功履歴、`run` だけの成功はゲートの代わりになりません。dbt build は全体を原子的に公開する処理ではなく、テスト失敗後も作成済みテーブルが残る点に注意します。
5. 定期化前に、別々のdbt呼び出し間の成功記録、重複起動防止、失敗通知、再試行時の入力版、成果物の公開切替、停止担当を設計・検証します。現行macroはtarget・選択範囲の検査であり、この実行管理の代用ではありません。MLの再学習・登録・推論は別途承認し、毎回の自動学習を前提にしません。固定文書の補足Searchをこの依存関係に加えません。

DCR と App Runtime の実装は含みません。定期実行基盤の準備も参加者の必須範囲ではありません。
